## 2026-11-23 — a build server, and what only showed there (0.16)

- Moved building, testing and measuring to a server: 32 processors, 125 GB of memory, ext4, nothing else running. Jato's suite passed there as it was. Olo's did not go as it had on the laptop, in four ways, all in the first hour.
- Nothing was put back. Every file of a build was opened before any was copied, and a process may have 1,024 files open: "Too many open files" in the log, and Cargo carried the build out. Files are now opened as they are copied, by the eight threads that copy them.
- No worktree got the clone's build: "`../.gitconfig` is gone". The clone was directly in the home directory, so git's settings were one step above the workspace and were recorded by the way there as well as by where they are. What a program keeps in the home directory under a name beginning with a dot is found by the home directory's name, and is now recorded only where it is.
- With every compilation answered, a check of all of Olo after a change to a manifest took 15 s, 30 of them in the kernel. Nearly all of that was Cargo: it starts each compiler as a copy of itself, so that the compiler inherits the pipe its tokens come through, and it had 290 MB to copy page tables for, 2,772 times, one at a time. Given a pipe with a name it starts compilers without the copy. Jato now makes one in the cache directory, with as many tokens as Cargo would have had, unless something says how many compilers to run or a make older than 4.4 is about. 11 s, 13 in the kernel, and at the start 1,300 answers a second where there had been 220.
- A compiler that takes a token from such a pipe reads and writes a file, and was not recorded for it. A pipe of tokens named in the environment is no longer among what a command examined.
- The first `build` in a worktree, after only `check` had been recorded, ran 1,228 compilers. 1,113 of them were what build scripts start, C and assembly mostly, the same commands as in the check but for one thing: Cargo puts `target/debug` in the loader's list of directories in a build. The list is no longer part of which command it is. It is kept with the result and compared by what the loader would find: 1,098 compilers now, none of them a build script's.
- The observer read each thread's whole status to learn its process, in pieces of a few hundred bytes: 131,000 reads for one build of 253 compilers. One read of the top of it now.
- `JATO_RECIPES` writes what each command is known by into a directory. Comparing two runs' directories found the loader's list in a minute, after an hour of reasoning had not.
- Measured there, Olo's check of the whole workspace: 82 s from nothing, 0.19 s again, 0.73 s in a new worktree, 5.1 s with a function added to `olo-system`, 11 s with a manifest changed. Cargo alone from nothing: 76 s, and the same with its target directory in memory.
- One of Olo's 56 programs names its checkout, so a `build` of the workspace was never put back in another worktree: 47 s, every compiler answered one at a time and 51 run. A whole build's record now says which compilers wrote output that names where it was made. A build somewhere else starts from it with those left out, as it starts from a build whose sources differ. 12 s: 5.6 s for 21,600 files, and `olo-fuzz` compiled. Output that names the place and is no compiler's of Cargo's, a file written beside the workspace for one, leaves nothing to start from as before.

A profile showed nothing but compression: each program has two names, the one Cargo links for people and the compiler's, linking changes the time the file's record was last changed, and so neither was known any more by what the compiler had stored. Both were compressed, to find the cache had them. A file is now read first, which is ten times quicker than compressing it, and one with two names is read once. 2.5 s.
- Measured there for the dev build of all of Olo: 194 s from nothing after a check, 5.3 s to put back, 12 s in a new worktree, 41 s in a new worktree with a function added to `olo-system` (57 compilers).

With more threads, each taking the next largest file, and the files moved into place and given their time by several threads where one had done it: 2.7 to 4 s. ## 2026-11-22 — git worktrees (0.14.1)

- Every whole build measured so far was made in a copy without a repository, or in a copy of one that was the same byte for byte. In a git checkout Cargo asks git which files a package has, for any package of the workspace whose build script has not said what it reads, and on a first build that is every package with a build script. It reads `HEAD`, the index, the configuration, the packed references and the list of packs. All of that differs in a worktree and in a clone, and the index changes with every commit. So a build was put back after `cargo clean` and never anywhere else: not in a worktree, which is where agents build.
- What Cargo itself reads in a repository's own directory is now left out of a build's inputs. All it takes from there is the list of files whose times it compares, and the files it then asks about are inputs as before. Cargo is told from what it starts by the program a process runs: the observer notes for each path whether any program other than the command's own used it. A build script that reads `.git/HEAD` still gets a build for each branch.
- The directories on the way to a repository, and those a workspace is inside, were inputs too: Cargo asks about each to find where a path really leads. A build made in a checkout that was deleted afterwards with the directory it was in could not be found again.
- The check of all of Olo, 121 packages, in a clone of the real repository: 574 s from nothing at a load of 32 to 77. In a worktree of that clone the build was put back in 1.9 s, and in the clone itself on another branch after a commit in 0.9 s.

A search goes through every directory on its way, and only names seen in places that follow one another from the workspace count as one now.

## 2026-11-22 — programs that tell of their own reads (0.14)

- A watched program used to wait for Jato at every call that names a file. Counted for one check of `olo-system`: 2,600 reported calls, and 18,000 more times that the command gave up the processor than unwatched. On a machine with every processor in use that is where the time went.
- Wrote a library of 14 KB that every watched program loads ahead of its C library. It stands in for `open`, `stat`, `access`, `opendir` and their relatives: for a call that only reads it sends a note of the path down a socket and makes the call from one fixed address, and the filter lets calls of those kinds through from that address alone, an open only if its flags neither create nor write. Calls that change anything are reported as before, since Jato has to look first, and so is everything from a program without the library. Notes are taken in ahead of each report, which keeps the order things happened in.
- The library needs nothing but `errno` and `fdopendir` from whatever C library the program has, names no library it depends on, and defines only the functions it stands in for. A first build of it left `rust_eh_personality` undefined, which would have kept it out of every program that is not Rust; defining it for all to see would have replaced rustc's own.
- rustc with Cargo's new layout lists a directory for every dependency: over 200 of them for `olo-system`, three reported calls each. A directory opened for reading now counts as listed and the calls that read entries are no longer reported, unless the command starts with a directory already open. The descriptor Jato gives a library's compiler for its target directory now only names the place.
- The same check: 160 reported calls, 3,000 more times giving up the processor than unwatched. Two cold checks of `olo-system` run side by side at a load of 50, one each way, both took 397.9 s: a build from nothing has slack that hides the waits. Compilations that someone is waiting for do not.
- A record is now turned down when a path the command found missing is there by the end. Between a program's note and its call the answer can change, and so it could between a report and the call.
- Qualified with 27 unit and 58 Cargo-project tests, with notes and with the kernel alone, on Rust 1.100 and 1.89 and with compressed storage.
